# Telink BLE Mesh для Home Assistant

Интеграция HACS для умных ламп на чипах **Telink** (BLE mesh, «телинковский» протокол
с логином по имени и паролю сети). Работает через встроенный Bluetooth Home Assistant,
то есть и через локальный адаптер, и через **ESPHome Bluetooth Proxy** на ESP32.

Такие лампы продаются под марками Lidl **Livarno LUX**, **Briloner**, **C by GE**,
а также в виде множества noname-ламп из приложений на базе Telink SDK.

## Как это работает

* Все лампы одной сети принимают одно и то же имя сети (mesh name) и пароль.
* Интеграция подключается **к одному любому узлу** (тому, у которого лучший сигнал)
  и через него управляет всеми лампами сети: узел ретранслирует команды дальше по mesh.
  Поэтому достаточно, чтобы хотя бы одна лампа находилась в зоне действия прокси.
* Лампы находятся автоматически по рекламным BLE-пакетам (производитель `0x0211`
  Telink, сервис `0x1910`, имя сети в scan response). После подключения список узлов
  дополняется отчётами самой сети (online-status, адресные отчёты).
* На каждую лампу создаётся сущность `light`, плюс одна сущность **«Все лампы»**,
  которая шлёт широковещательную команду сразу всей сети.

## Установка

### HACS

1. HACS → Integrations → меню (⋮) → **Custom repositories**.
2. Добавьте URL репозитория, категория **Integration**.
3. Установите «Telink BLE Mesh» и перезапустите Home Assistant.

### Вручную

Скопируйте папку `custom_components/telink_mesh` в `config/custom_components/`
и перезапустите Home Assistant.

## Настройка

Как только лампа окажется в зоне действия Bluetooth, Home Assistant сам предложит
добавить интеграцию («Обнаружено: Telink mesh <имя>»). Также можно добавить вручную:
**Настройки → Устройства и службы → Добавить интеграцию → Telink BLE Mesh**.

### Шаг 1. Выбор профиля продукта

Первый экран предлагает выбрать **профиль**. Профиль автоматически подставляет имя
сети, пароль и подходящий набор команд для известной модели:

| Профиль | Имя сети | Пароль | Набор команд |
| --- | --- | --- | --- |
| **Mesh Lamp / Fulife** | `Fulife` | `2846` | Livarno (`0xF0/0xF1`) |
| **Ручной ввод** | — | — | вводится вручную |

Профиль «Mesh Lamp» подходит для ламп бренда Fulife и других устройств, управляемых
приложением **Mesh Lamp** (`com.telink.bluetooth.mesh_lamp`). Эти имя и пароль зашиты
в приложении и одинаковы для всех таких ламп.

Чтобы добавить свой профиль, впишите его в словарь `CREDENTIAL_PRESETS`
в файле `custom_components/telink_mesh/const.py`.

### Шаг 2. Проверка и правка данных

На втором экране показываются подставленные значения — их можно изменить:

| Поле | Описание |
| --- | --- |
| Имя mesh-сети | Заводское значение Telink: `telink_mesh1`. |
| Пароль mesh-сети | Заводское значение Telink: `123`. Производители обычно меняют оба значения. |
| Набор команд | `Livarno / Briloner` (`0xF0/0xF1`, как в telinkpp) или `Стандартный Telink SDK` (`0xD0/0xD2/0xE2`). Если лампы не реагируют на яркость/цвет, попробуйте другой. |
| Возможности ламп | RGB+CCT, только RGB, только CCT, диммер или вкл/выкл. Влияет на то, какие регуляторы показывает Home Assistant. |

Все параметры, кроме имени сети, можно поменять позже в **Настроить** (options):
там же есть «отправка с подтверждением» (помогает на некоторых прокси) и интервал опроса.

## Как узнать имя и пароль mesh-сети

Пользователь в фирменном приложении этих значений не видит: лампа добавляется
«автоматически», а имя и пароль зашиты в само приложение. Для интеграции их нужно
достать один раз. Ниже три способа, от простого к сложному.

### Способ 1. Готовый профиль

Если ваша лампа управляется приложением **Mesh Lamp** (бренд Fulife и аналоги),
просто выберите профиль **Mesh Lamp / Fulife** — данные уже заполнены.

### Способ 2. Логи Bluetooth на Android (рекомендуется)

Приложение при подключении отправляет лампе логин-пакет, из которого имя и пароль
восстанавливаются офлайн.

1. На телефоне: **Настройки → Для разработчиков → Включить журнал HCI Bluetooth**
   (Enable Bluetooth HCI snoop log). Если приложение производителя пишет отладочный
   лог в logcat (как Mesh Lamp с тегом `TelinkBluetoothSDK`), достаточно снять
   `adb logcat`.
2. Откройте приложение и подключитесь к лампе, чтобы прошёл вход в сеть.
3. Снимите лог: `adb logcat -d > bluetooth.txt` (или заберите HCI-снуп-файл
   и откройте в Wireshark).
4. Найдите запись в характеристику `…1914` вида
   `0C,<8 байт>,<8 байт>` — это пакет входа. Первый байт `0C`, дальше 8 случайных
   байт и 8 байт зашифрованной подписи.
5. По этому пакету подберите имя и пароль офлайн скриптом из `tools/` (см. ниже).
   Заводской пароль часто короткий и числовой, а имя совпадает с рекламным именем
   лампы, поэтому подбор занимает секунды.

Важно: в самом пакете имя и пароль в открытом виде не лежат, но так как в подписи
известны 8 из 8 нужных байт при известных случайных байтах, кандидаты имя/пароль
проверяются мгновенно.

### Способ 3. Декомпиляция приложения

Имя и пароль часто зашиты константами в APK. Декомпилируйте приложение
(например, через [JADX](https://github.com/skylot/jadx)) и поищите строки рядом с
`meshName`, `meshPassword`, `Manufacture`, `out_of_mesh`. Подробный разбор с отладкой
приложения описан в разделе *Finding device name and password* проекта
[telinkpp](https://github.com/vpaeder/telinkpp).

Для ламп, которые никогда не подключались к приложению, работают заводские
`telink_mesh1` / `123`.

## ESPHome Bluetooth Proxy

Нужен **активный** режим (соединения через прокси):

```yaml
esp32_ble_tracker:
  scan_parameters:
    active: true   # нужен scan response, в нём передаётся имя mesh-сети

bluetooth_proxy:
  active: true
```

## Отладка

Диагностику можно скачать со страницы интеграции (пароль вырезается).
Подробный лог:

```yaml
logger:
  logs:
    custom_components.telink_mesh: debug
```

В атрибутах каждой лампы видны `mesh_id`, `mac`, `rssi` и `connected_via`
(адрес узла, через который сейчас идёт управление).

## Ограничения

* Нужен Home Assistant 2025.1 или новее.
* Сценарии, будильники и группы ламп (адреса `0x8000+`) протокол поддерживает,
  но в интеграции пока не реализованы.
* Формат отчёта о цвете (`0xDB`) проверен по telinkpp для ламп Livarno; для
  «стандартного» профиля цвет обновляется оптимистично после команды.

## Разработка

Протокол (шифрование, сборка пакетов, парсинг) лежит в `protocol.py` и не зависит
от Home Assistant. Тесты сверяют его с эталонной реализацией python-dimond и
проверяют, что профиль «Mesh Lamp» воспроизводит реальные логин-пакеты:

```bash
python3 -m unittest discover -s tests -v
```

Восстановление имени и пароля из перехваченного логин-пакета:

```bash
python3 tools/recover_credentials.py "0C,<random8>,<sig8>" ["0C,..."]
```
